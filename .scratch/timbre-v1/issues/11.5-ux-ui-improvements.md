# 11.5: UX/UI improvements

**What to build:** a polish pass on the home page and the results. The UI fades in in sequence once the waveform background is ready. After a search, the search box sits in a sticky compact top bar. Results fill the page width, cards are redesigned with the album cover and animate in, and the Spotify Preview dock becomes a smaller floating player.

**Blocked by:** 11

**Status:** ready-for-agent

Owner decisions come from the planning conversation of 2026-11-10. Use the skills `ecc:motion-foundations` and `ecc:make-interfaces-feel-better` for this ticket. Add no new animation dependency: use `tw-animate-css` (already installed), CSS and the View Transitions API.

## Entrance animation

- [ ] The UI stays hidden until the WebGL background has drawn its first frame. Then it fades in, in sequence, top to bottom, with a short delay between steps: **top bar → search box → suggestion chips → footer**.
- [ ] Safety nets: if WebGL2 is unavailable (`waveform-background.tsx` returns early), or the background isn't ready after about 1 s, the UI shows anyway. The hidden starting state applies only under `@media (scripting: enabled)`, so the page is never blank without JavaScript.
- [ ] `prefers-reduced-motion`: no fades or movement. Elements appear at once.

## Search and top bar

- [ ] The logo text ("timbre.") can't be selected (`select-none`).
- [ ] The search input shows no browser history/autofill dropdown (`autoComplete="off"`). Spell-check stays as it is.
- [ ] After a search (`q` present), the search box is placed at the top in a sticky compact bar, laid out as **`<Logo> <input> <search button>`**, side by side. The bar stays visible while the song list scrolls. The theme toggle stays available in both states.
- [ ] The compact bar has no info note ("Descrições e votos são armazenados…"). The note stays on the home (hero) layout.
- [ ] The move from hero to compact bar is a View Transitions API morph (shared `view-transition-name` on logo and form), **300 ms**. Browsers without support switch instantly. Reduced motion: no morph.
- [ ] Small screens: the compact bar shows the short logo **"t."** and an **icon-only** search button (Lucide `Search`, with an accessible name).

## Results

- [ ] The "Resultados" section fills the page width, with a 16 px gutter from the viewport edges (outside today's `max-w-5xl` wrapper).
- [ ] After a search, the cards fade in one by one, each card its own animation, with a small stagger (about 30 ms per card), capped so a page of 60 doesn't take seconds. Cards added by "Carregar mais" stagger from the first new card.
- [ ] Update `front/lib/grid.ts` to the new layout: no 1024 px max width, the new card size, and the sticky bar's height, so N still fills about one screen. Its Vitest tests follow.
- [ ] Short phone screens: less padding and smaller gaps between cards. The layout stays responsive from 320 px phones to wide desktops.

## Card

- [ ] Layout, aimed at making it clear what each card is and how to preview it:

  ```
  ┌───────────────────────────────────────────┐
  │ ┌──────┐  Song title (semibold, 2 lines) 👍👎│
  │ │ cover│  Artist (muted)                    │
  │ │ 64px │                                    │
  │ └──────┘  [▶ Prévia]                    (●) │  ← Spotify icon link
  └───────────────────────────────────────────┘
  ```

- [ ] **Album cover** on the left, from Spotify. Backend:
  - store the album image URL (smallest image ≥ 64 px from the Search response's `album.images`, so no extra Spotify calls) in `preview.spotify_cache`, with the same 24 h TTL, via a new dbmate migration;
  - return it in the `Preview` model;
  - regenerate `back/openapi.json` and `front/lib/api/schema.d.ts`;
  - add backend tests.
- [ ] Spotify artwork rules (`docs/research/spotify-platform-terms.md` §6): original form, no crop, no overlay, no blur, no animation of the image itself, rounded 4 px. The hover border goes around the card, never over the cover. The cover's `alt` is empty, because the title is right next to it.
- [ ] **No cover** (Song not on Spotify, or no image): a placeholder with the Lucide `Music` icon. Dark theme: dark background, lighter border, white icon. Light theme: the opposite (light background, darker border, dark icon). Instead of an empty space, a short muted line "Prévia indisponível".
- [ ] **Spotify link becomes the icon only**: the official Spotify icon SVG, black and white variants like `BrandLogo`, at least 21 px, on a link to the track. Add the files to `front/public/`. No "LISTEN ON SPOTIFY" text. Accessible: `aria-label="Listen on Spotify: <title>"` (or equivalent), visible focus ring, and a 44 px touch target.
- [ ] **Prévia button** shows the state: "⏸ Tocando" while this card's track plays (the player context already knows `playing.uri`), and "▶ Prévia" otherwise.
- [ ] **Prévia hover** is colourful: the brand indigo→mauve gradient, with dark text that stays AA.
- [ ] **Card hover**: the card's border fades in with the app's theme gradient (reuse the `gradient-border` utility), and the gradient moves (rotates slowly, `@property --angle`) only while hovered. It fades out slowly when the pointer leaves. Reduced motion: fade only, no rotation.

## Spotify Preview dock

- [ ] The dock becomes a floating, centred player with rounded corners, sitting a little above the bottom edge (about 12–16 px). Drop the full-width frosted strip and its padding, so the dock is exactly the embed's height (80 px, Spotify's smallest; it can't be smaller).
- [ ] Width depends on the screen but stays smaller than today's 1024 px: full width minus the 16 px gutters on phones, growing with the viewport on larger screens (for example `clamp` to about 60 vw), capped around 768 px.
- [ ] Remove the white border around the embed. Find which cause it is: either the iframe's default border (`border: 0`), or the iframe's own background showing around Spotify's rounded corners. For the second, use a wrapper with `overflow-hidden` and the embed's corner radius, which trims only the empty corners, never the player.
- [ ] If the iFrame API (or the embed URL) supports Spotify's `theme=0` (neutral dark background), use it. Check Spotify's docs first. If it isn't supported, leave the embed's colour as it is.
- [ ] Nothing inside the embed is covered, cropped or changed (Widget Terms, ADR 0001). The page's bottom space (`has-data-[dock=open]:pb-28`) shrinks to match the new dock.

## Testing

- [ ] Lint, `tsc --noEmit`, prettier, Vitest, ruff, mypy and pyright pass. Backend tests run in Compose.
- [ ] **No local Playwright e2e.** CI runs it. Update the e2e specs this ticket breaks (`home.spec.ts`, `preview.spec.ts`: "LISTEN ON SPOTIFY", the hero layout, the dock). Set `reducedMotion: 'reduce'` in the Playwright config, so the axe contrast checks never measure a half-faded element.
