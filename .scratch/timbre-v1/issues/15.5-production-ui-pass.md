# 15.5: Production UI pass

**What to build:** a design pass on the home page and the results before going live, following the frontend-design skill (https://github.com/anthropics/skills/blob/main/skills/frontend-design/SKILL.md). The UI looks deliberate rather than templated, keyboard focus is clearly visible, and the app has its own icons and link previews. A search also feels real: after "Pesquisar", the card skeletons show while the search panel moves to the top, and the search request is sent only once that animation has finished.

**Blocked by:** 11.5

**Status:** ready-for-agent

Owner decisions come from the audit conversation of 2026-11-17. Where an item below changes an earlier ticket's rule, this ticket wins; the earlier rule is named.

## Fixes

- [ ] **Visible keyboard focus:** buttons and the input today use `ring-1 ring-ring/50`, which is almost invisible in Dark. Give them a 2 px solid focus ring, like the cards and the logo link already have (`focus-visible:ring-2 focus-visible:ring-foreground`), in both themes.
- [ ] **One family of corner radii:** the input and the buttons have square corners (`rounded-none` in `components/ui/input.tsx` and `components/ui/button.tsx`, left over from the old shadcn style), while the panel, cards and chips are rounded. Round the input and buttons to match (for example `rounded-lg`, from the `--radius` tokens). The icon-only round buttons (theme toggle, Spotify) keep their full rounding.
- [ ] **App icon, link previews and theme colour:** add a favicon / app icon (`app/icon`), an Apple touch icon (`app/apple-icon`), an Open Graph and Twitter image (`app/opengraph-image`, via `next/og`) showing "timbre." and the hero line below, and `themeColor` for Light and Dark through the `viewport` export. Use the logo typeface chosen under **Typeface**.
- [ ] **Helpful empty state:** "Nenhuma música encontrada" becomes "Nenhuma música encontrada. Tente descrever o clima ou os instrumentos, ou use um exemplo:", followed by the sample chips that are already there. It stays a `role="status"`.
- [ ] **Chips in the palette:** the sample Description chips are plain grey (`variant="secondary"`), the only surfaces outside the indigo/mauve palette. Tint them to match the glass and brand colours in both themes. Text stays AA.
- [ ] **Themed scrollbar:** the cards area's scrollbar is the browser's default grey, which clashes in Dark. Theme it with `scrollbar-color` (and `scrollbar-width: thin`) from the theme tokens.
- [ ] **Placeholder:** "Descreva sua música favorita..." uses the real ellipsis: "Descreva sua música favorita…".
- [ ] **Even hero border:** the hero search panel's border looks thicker or darker along the bottom edge than on the other sides (owner screenshot, Light theme). Find the root cause (for example the `gradient-border` `::before`, the `frosted` backdrop blur sampling past the panel's edge, the hover shadow, or `Card`'s own ring) and fix it there, so the border is even on all four sides in both themes.

## Motion (decision A)

- [ ] Keep the one orchestrated page entrance (ticket 11.5: top bar → search box → chips → footer) and the hero → compact bar morph.
- [ ] **Drop the per-card stagger:** result cards no longer fade in one by one. They appear together with their step of the entrance. On a later search or "Carregar mais", they appear at once. This replaces ticket 11.5's "cards fade in one by one, ~30 ms stagger". Remove whatever only served the stagger (`STAGGER_*`, `CARD_ENTER_MS`, `enterTiming`, `--card-entered`, the cover's `after-card-enter` wait), unless something else still needs it. Spotify artwork is still never animated.
- [ ] **Keep the rotating gradient border on card hover**, as ticket 11.5 describes (fades in, turns slowly while hovered, fades out slowly; reduced motion: fade only). Make it **1 px thicker: 2 px** on the cards. The hero panel's border stays 1 px.
